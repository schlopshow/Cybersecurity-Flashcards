What is the purpose of persistence in Active Directory?|To maintain access to a target environment even after remediation efforts like credential rotations and patching, ensuring continued control
What are the two main categories of persistence techniques?|Active Directory persistence (domain-level techniques like Golden/Silver tickets, DCSync backdoors, AdminSDHolder abuse) and OS-level persistence (local techniques like scheduled tasks, services, registry modifications, DLL hijacking)
What is a Golden Ticket attack?|An attack that forges a TGT (Ticket Granting Ticket) by using the KRBTGT account's password hash, allowing the attacker to impersonate any user and access any service within the domain
What account's hash is needed for a Golden Ticket?|The KRBTGT account's NTLM hash or AES key
What is the KRBTGT account?|A special account in Active Directory used to encrypt and sign all Kerberos tickets (TGTs) within the domain; it is the foundation of the Kerberos authentication system
What is the default lifetime of a Golden Ticket?|10 years by default
Why is a Golden Ticket particularly dangerous?|Because it is forged offline, does not require communication with a Domain Controller during creation, and remains valid until the KRBTGT password is changed twice
How do you mitigate Golden Ticket attacks?|Reset the KRBTGT password twice (to invalidate both current and previous hashes), implement regular KRBTGT password rotation, monitor for anomalous TGT usage, and use Privileged Access Workstations
Why must the KRBTGT password be reset twice?|Because Active Directory stores the current and previous password hashes; resetting twice invalidates both, ensuring no old Golden Tickets remain valid
What is a Silver Ticket attack?|An attack that forges a TGS (Ticket Granting Service) for a specific service by using the service account's NTLM hash, granting access to that particular service without contacting the KDC
What is the key difference between Golden and Silver Tickets?|Golden Tickets forge TGTs (access to any service, require KRBTGT hash), while Silver Tickets forge TGS tickets (access to a specific service only, require the service account's hash)
What are the advantages of Silver Tickets over Golden Tickets?|More stealthy since they don't interact with the Domain Controller, harder to detect, and only require a service account hash rather than the KRBTGT hash
What is the limitation of Silver Tickets?|They only grant access to the specific service for which the ticket was forged, not the entire domain
What services are commonly targeted with Silver Tickets?|CIFS (file shares), HOST (task scheduling, PSExec), HTTP (WinRM, PowerShell Remoting), MSSQL (database access), LDAP (DCSync operations)
How do you detect Silver Ticket attacks?|Monitor for TGS tickets without corresponding TGT requests, look for Event ID 4769 anomalies, check for tickets with unusual lifetimes, and implement service account credential rotation
What is a Diamond Ticket attack?|An attack that modifies a legitimately requested TGT by decrypting it with the KRBTGT hash, changing desired fields (like adding privileged group memberships), and re-encrypting it
Why are Diamond Tickets harder to detect than Golden Tickets?|Because they are based on a real TGT with valid ticket properties, making them blend in with normal Kerberos traffic rather than being entirely forged
What tool creates Diamond Tickets?|Rubeus with the diamond function
What is a Sapphire Ticket attack?|An attack similar to Diamond Tickets but using S4U2Self and U2U extensions to obtain a legitimate PAC for another user, then inserting it into the modified ticket
Why are Sapphire Tickets the most difficult to detect?|Because the PAC inside the ticket is a legitimately-generated one from the KDC, so even if the PAC signature is validated, it appears completely authentic
What is the difference between Diamond and Sapphire Tickets?|Diamond Tickets modify an existing PAC with arbitrary values, while Sapphire Tickets obtain and use a completely legitimate PAC from the KDC for the target user
What is DCSync?|A technique that simulates the behavior of a Domain Controller requesting replication data using the MS-DRSR protocol, allowing extraction of password hashes from Active Directory
What three rights are required for DCSync?|Replicating Directory Changes (DS-Replication-Get-Changes), Replicating Directory Changes All (DS-Replication-Get-Changes-All), and optionally Replicating Directory Changes in Filtered Set
What is a DCSync Backdoor?|A persistence technique where replication rights are granted to a controlled account, allowing that account to perform DCSync attacks at any time to extract credentials
What accounts normally have DCSync rights?|Domain Admins, Enterprise Admins, Domain Controllers, and the Administrators group
How is a DCSync Backdoor detected?|By monitoring changes to the domain object's ACL, specifically new entries granting replication rights, using Event ID 5136 (Directory Service Changes)
What is AdminSDHolder?|An Active Directory container whose ACL serves as a template for all protected groups and their members; the SDProp process copies its ACL to protected objects every 60 minutes
What is the SDProp process?|Security Descriptor Propagation - a process that runs every 60 minutes to overwrite ACLs on protected objects with the ACL from the AdminSDHolder container
What groups are protected by AdminSDHolder?|Account Operators, Administrators, Backup Operators, Domain Admins, Domain Controllers, Enterprise Admins, Print Operators, Read-only Domain Controllers, Replicator, Schema Admins, and Server Operators
How is AdminSDHolder abused for persistence?|By adding a controlled user or group to the AdminSDHolder ACL with specific permissions (like GenericAll), which then propagates to all protected accounts every 60 minutes
Why is AdminSDHolder abuse effective for persistence?|Even if the ACL on the target objects is manually fixed, the SDProp process will overwrite it within 60 minutes with the backdoored AdminSDHolder ACL
How do you detect AdminSDHolder abuse?|Monitor modifications to the AdminSDHolder container's ACL using Event ID 5136, regularly audit the AdminSDHolder ACL, and compare it against a known-good baseline
What is the Security Support Provider (SSP) persistence technique?|Loading a malicious SSP DLL into LSASS that intercepts authentication credentials in plaintext during the logon process
What is an SSP (Security Support Provider)?|A DLL that provides security mechanisms for applications and infrastructure services, loaded into LSASS at startup and capable of accessing stored credentials and authentication data in plaintext
How can a malicious SSP be loaded into LSASS?|Either by adding the DLL to the SSP registry key (requires restart) or by using in-memory injection via AddSecurityPackage API call (immediate but not persistent across reboots)
What registry key stores SSP packages?|HKLM\SYSTEM\CurrentControlSet\Control\Lsa\Security Packages
What is mimilib.dll?|A custom SSP from the Mimikatz project that logs all credentials in plaintext to a file called kiwissp.log
How do you detect SSP-based persistence?|Monitor changes to the LSA Security Packages registry key, audit DLLs loaded by LSASS, use Sysmon Event ID 7 for DLL loading, and monitor AddSecurityPackage API calls
What is the Skeleton Key attack?|An attack that patches the LSASS process on a Domain Controller to add a master password (by default "mimikatz") that works alongside every user's real password
How does a Skeleton Key work?|It modifies the NTLM and Kerberos authentication process in memory on the DC, allowing the attacker's master password to be accepted as valid for any account while legitimate passwords continue to work
What are the limitations of the Skeleton Key attack?|It's in-memory only (lost on DC reboot), must be re-applied to each DC, may cause instability, and doesn't work if LSASS is protected with RunAsPPL
What is RunAsPPL?|A security feature that runs LSASS as a Protected Process Light, preventing unauthorized code from being injected into it, which blocks attacks like Skeleton Key
How do you detect a Skeleton Key attack?|Monitor for unauthorized access to LSASS, look for Kerberos authentication anomalies (downgrade to RC4), use Event ID 4673 and 4611, and implement LSASS protection with RunAsPPL
What is the SID History persistence technique?|Injecting privileged SIDs (like Domain Admins SID) into a user's SID History attribute, granting them associated privileges without being a direct member of the privileged group
What is the SID History attribute?|An Active Directory attribute that stores previous Security Identifiers, originally designed for migration scenarios to maintain access to resources from a previous domain
Why is SID History persistence stealthy?|Because the user doesn't appear as a member of the privileged group in standard group membership queries, yet receives all the privileges associated with the injected SID
How do you detect SID History abuse?|Monitor for Event ID 4765 (SID History added) and 4766 (failed attempt), audit SID History attributes regularly, and look for SIDs from the same domain in the history (which is abnormal)
What is the GoldenGMSA attack?|An attack that extracts the KDS Root Key from Active Directory to compute gMSA (Group Managed Service Account) passwords offline, without querying the gMSA attributes directly
What makes GoldenGMSA particularly dangerous as a persistence technique?|Once the KDS Root Key is obtained, the attacker can compute gMSA passwords at any time without additional AD queries, and the key rarely changes
What is the KDS Root Key?|Key Distribution Service Root Key - the master key used to derive gMSA passwords; it rarely changes and can be used to compute passwords for any gMSA in the forest
How do you mitigate GoldenGMSA attacks?|Strictly limit who can access KDS Root Key objects, monitor access to KDS Root Key attributes, regularly rotate gMSA passwords, and consider creating new KDS Root Keys if compromise is suspected
What is the DSRM (Directory Services Restore Mode) persistence technique?|Using the DSRM administrator account on Domain Controllers as a backdoor by changing a registry value to allow network logon with this local account
What is the DSRM administrator account?|A local administrator account on every Domain Controller created during AD DS promotion, with a password set at that time and rarely changed thereafter
What registry value must be changed for DSRM persistence?|DsrmAdminLogonBehavior under HKLM\SYSTEM\CurrentControlSet\Control\Lsa, changed to value 2 to allow network logon
What are the three DsrmAdminLogonBehavior values?|0 (default - only in DSRM), 1 (logon when AD DS is stopped), 2 (logon at any time - the value needed for persistence)
How do you detect DSRM abuse?|Monitor changes to the DsrmAdminLogonBehavior registry key, audit logon events using the DSRM account (Event ID 4794), and regularly rotate the DSRM password
What is the Print Spooler persistence technique?|Abusing the Windows Print Spooler service to load malicious DLLs as print monitors, which get loaded by LSASS at system startup with SYSTEM privileges
What registry key is used for Print Monitor persistence?|HKLM\SYSTEM\CurrentControlSet\Control\Print\Monitors\[MonitorName] with a Driver value pointing to the malicious DLL
Why is Print Monitor persistence effective?|The DLL is loaded by spoolsv.exe (which runs as SYSTEM), starts automatically with Windows, and print monitors are rarely audited
How do you detect Print Monitor persistence?|Monitor registry changes under the Print\Monitors key, audit DLLs loaded by spoolsv.exe, and use Sysmon Event ID 12/13 for registry modifications
What is the Computer Account persistence technique?|Creating or modifying computer accounts to use them as persistence mechanisms, since computer accounts can authenticate to the domain and are often less monitored than user accounts
How can computer accounts be used for persistence?|By changing the computer account password to a known value, adding it to privileged groups, or modifying its properties to enable it as a regular authentication account
What property must be changed on a computer account to use it like a user account?|The userAccountControl attribute, specifically removing the WORKSTATION_TRUST_ACCOUNT flag and setting it to a normal account type
Why are computer accounts good for persistence?|They are less scrutinized than user accounts, have passwords that change every 30 days by default (but this can be disabled), and their names end with $ making them less visible
What are Certificate-based persistence techniques?|Techniques that abuse Active Directory Certificate Services (AD CS) to maintain access, including forging certificates, stealing CA private keys, and modifying certificate templates
What is the PERSIST1 technique (user certificate request)?|Requesting a certificate for the compromised user from a template that allows client authentication, then using that certificate to authenticate even after password changes
Why does PERSIST1 survive password changes?|Because certificate-based authentication is independent of password-based authentication; the certificate remains valid until it expires regardless of password changes
What is the PERSIST2 technique (machine certificate request)?|Requesting a machine certificate that allows authentication as the computer account, which can then be used for operations like S4U2Self to access the machine as any user
What is the PERSIST3 technique (CA private key theft)?|Stealing the Certificate Authority's private key, allowing the attacker to forge any certificate for any user or machine in the environment
Why is PERSIST3 (CA key theft) the most devastating AD CS persistence technique?|Because with the CA private key, the attacker can forge certificates for any identity in the domain, and remediation requires revoking the CA and rebuilding the entire PKI infrastructure
How do you detect AD CS-based persistence?|Monitor certificate enrollment events (Event ID 4886, 4887), audit certificate template modifications, track CA private key access, and implement certificate lifecycle monitoring
What is the difference between OS-level and AD-level persistence?|OS-level persistence survives on a single machine (scheduled tasks, services, registry), while AD-level persistence provides domain-wide access that survives individual machine remediation
What is Scheduled Task persistence?|Creating a Windows scheduled task that executes a payload at specified intervals, on user logon, or at system startup to maintain access to a single machine
What registry locations are used for Run Key persistence?|HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run (all users) and HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run (current user)
What is DLL Hijacking for persistence?|Placing a malicious DLL in a location where a legitimate application will load it instead of the intended DLL, exploiting the Windows DLL search order
What is DLL Side-Loading?|A specific type of DLL hijacking where a malicious DLL is placed alongside a legitimate application that loads DLLs from its own directory first
What is COM Object Hijacking for persistence?|Modifying COM object registry entries to point to malicious code, which executes whenever the COM object is instantiated by a legitimate application
What is WMI Event Subscription persistence?|Using WMI permanent event subscriptions (consisting of an event filter, event consumer, and binding) to execute commands when specific system events occur
What three components make up a WMI Event Subscription?|An Event Filter (defines the trigger condition), an Event Consumer (defines the action to perform), and a Filter-to-Consumer Binding (links the filter to the consumer)
What is the advantage of WMI Event Subscription persistence?|It is fileless (stored in the WMI repository), survives reboots, can be triggered by various system events, and is difficult to discover without specific WMI querying
What is Service persistence?|Creating or modifying a Windows service to execute a malicious payload, providing SYSTEM-level execution that starts automatically with the system
What is the IFEO (Image File Execution Options) persistence technique?|Setting a Debugger value in the IFEO registry key for a commonly used application, causing the malicious payload to execute whenever that application is launched
What registry path is used for IFEO persistence?|HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\[application.exe]
What is AppInit_DLLs persistence?|Loading malicious DLLs into every user-mode process that loads user32.dll by adding the DLL path to the AppInit_DLLs registry value
What is Startup Folder persistence?|Placing a malicious executable or shortcut in the Windows Startup folder so it runs automatically when a user logs in
What are the two Startup folder locations?|Per-user (C:\Users\[Username]\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup) and all-users (C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup)
What is the difference between HKLM and HKCU Run key persistence?|HKLM Run keys execute for all users and require admin privileges to modify; HKCU Run keys execute only for the current user and don't require admin privileges
What is a Logon Script persistence technique?|Configuring a script in the UserInitMprLogonScript registry value or through Group Policy that executes every time the user logs on
What is the general approach to detecting AD persistence?|Implement comprehensive logging and monitoring, establish baselines for normal behavior, use multiple detection mechanisms, conduct regular AD security assessments, and deploy honeypot/canary objects
What are Canary objects in AD persistence detection?|Decoy accounts or objects with monitored access that trigger alerts when accessed or modified, helping detect unauthorized enumeration or persistence activities
What is the recommended remediation approach when AD persistence is discovered?|Assume the entire domain is compromised, reset the KRBTGT password twice, rotate all privileged account credentials, audit all persistence mechanisms, rebuild compromised systems, and review all trust relationships
What is YOUREXPLOIT in the context of persistence?|It's a reminder that attackers always look for novel or creative persistence mechanisms not covered by standard detection, emphasizing that persistence techniques continue to evolve
What Event ID indicates a Kerberos ticket was requested?|Event ID 4768 (TGT request) and Event ID 4769 (TGS request)
What Event ID indicates directory service object modification?|Event ID 5136, useful for detecting DCSync backdoor creation and AdminSDHolder modifications
What Event ID indicates SID History was added to an account?|Event ID 4765 (SID History added successfully) and Event ID 4766 (failed attempt to add SID History)
What is the relationship between persistence and privilege escalation?|Many persistence techniques require prior privilege escalation (such as Domain Admin access for Golden Tickets), while some persistence techniques themselves enable further privilege escalation
Why is the KRBTGT account the most critical account for domain security?|Because it signs and encrypts all TGTs - compromise of this account allows forging Golden Tickets and Diamond Tickets, effectively owning the entire domain authentication system
What determines which Kerberos ticket attack to use?|If you have the KRBTGT hash, use Golden/Diamond/Sapphire tickets for domain-wide access; if you only have a service account hash, use Silver Tickets for targeted service access
What is PAC (Privilege Attribute Certificate)?|A structure within Kerberos tickets containing authorization data like group memberships, user rights, and additional credential information used by services for access control decisions
Why is monitoring LSASS critical for detecting persistence?|Many persistence techniques (SSP loading, Skeleton Key, credential dumping) require interacting with or modifying the LSASS process, making it a key indicator of compromise
What is the significance of the 60-minute SDProp cycle for AdminSDHolder persistence?|Even if defenders manually remove malicious ACLs from protected objects, the SDProp process will re-apply the backdoored AdminSDHolder ACL within 60 minutes, making remediation difficult without fixing AdminSDHolder itself
